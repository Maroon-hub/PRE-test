# Example Output Format

This document shows example output files generated by the structural inference tool.

## records.jsonl Example

Each line is a JSON object representing one protocol record:

```json
{"pcap_file": "modbus_capture.pcap", "port": 502, "tcp_stream": 0, "follow_dir": 0, "flow_id": "192.168.1.10:45678->192.168.1.20:502", "record_id": 0, "t0": 1234567890.123456, "t1": 1234567890.125789, "raw_len": 12, "sha256": "5f8a7b3c9d2e1a4f6c8b7a5e3d9c1b2a4f6e8d7c5b3a1f9e7d5c3b1a9f8e7d6c", "header_window_end": 12, "boundaries": [2, 6, 12]}
{"pcap_file": "modbus_capture.pcap", "port": 502, "tcp_stream": 0, "follow_dir": 1, "flow_id": "192.168.1.20:502->192.168.1.10:45678", "record_id": 0, "t0": 1234567890.126543, "t1": 1234567890.127234, "raw_len": 8, "sha256": "3c2d1e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d", "header_window_end": 8, "boundaries": [2, 6, 8]}
```

**Fields:**
- `pcap_file`: Source pcap filename
- `port`: TCP port filtered
- `tcp_stream`: Stream ID from tshark
- `follow_dir`: Direction (0 or 1)
- `flow_id`: Flow identifier (src:port->dst:port)
- `record_id`: Sequential ID within the flow
- `t0`, `t1`: Start/end timestamps (epoch seconds)
- `raw_len`: Record length in bytes
- `sha256`: SHA-256 hash (raw bytes NOT included for privacy)
- `header_window_end`: End of header analysis window
- `boundaries`: Inferred structural boundaries

## schema.json Example

Global schema with boundary inference results:

```json
{
  "meta": {
    "tool": "reverse_structural.py",
    "version": "1.0",
    "pcap_dir": "/path/to/pcaps",
    "port": 502,
    "gap_ms": 500.0,
    "max_record_bytes": 262144,
    "header_max_bytes": 64,
    "num_records": 150,
    "num_pcaps": 3
  },
  "global_boundaries": [2, 6, 8],
  "segment_stats": [
    {
      "start": 0,
      "end": 2,
      "presence": 1.0,
      "len_mean": 2.0,
      "len_std": 0.0,
      "entropy_mean": 0.5
    },
    {
      "start": 2,
      "end": 6,
      "presence": 0.95,
      "len_mean": 4.0,
      "len_std": 0.2,
      "entropy_mean": 1.2
    },
    {
      "start": 6,
      "end": 8,
      "presence": 0.87,
      "len_mean": 2.0,
      "len_std": 0.3,
      "entropy_mean": 2.1
    }
  ]
}
```

**Schema Fields:**

- `meta`: Metadata about the analysis
  - `tool`, `version`: Tool identification
  - `pcap_dir`, `port`: Input parameters
  - `gap_ms`, `max_record_bytes`, `header_max_bytes`: Algorithm parameters
  - `num_records`, `num_pcaps`: Statistics
  
- `global_boundaries`: List of boundary positions (byte offsets) found across all records
  
- `segment_stats`: Statistics for each segment (region between boundaries)
  - `start`, `end`: Segment byte range
  - `presence`: Proportion of records containing this segment (0.0 to 1.0)
  - `len_mean`, `len_std`: Mean and standard deviation of segment lengths
  - `entropy_mean`: Mean Shannon entropy of segment contents (bits per byte, 0.0 to 8.0)

## Interpretation

The inferred boundaries represent likely field boundaries in the protocol format. For example:

- Boundary at position 2: First 2 bytes likely form a header field (e.g., transaction ID, protocol ID)
- Boundary at position 6: Bytes 2-5 likely form another field (e.g., length, function code)
- Boundary at position 8: Bytes 6-7 likely form another field (e.g., address, count)

High `presence` (close to 1.0) indicates the segment appears in most records.
Low `len_std` indicates consistent segment length.
High `entropy_mean` indicates variable/encrypted content, low entropy indicates structured/repetitive content.
